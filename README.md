# FastAPI Production Template

A production-ready FastAPI boilerplate built with a domain-based architecture.

It includes authentication, user management, JWT access and refresh tokens, PostgreSQL, SQLAlchemy, Alembic migrations, and Docker support.

## Features

* FastAPI
* Domain-based project architecture
* Authentication domain
* User domain
* JWT access tokens
* JWT refresh tokens
* SQLAlchemy ORM
* Alembic database migrations
* PostgreSQL
* Docker
* Docker Compose
* Environment-based configuration
* Modular and scalable project structure

## Tech Stack

* **Framework:** FastAPI
* **Database:** PostgreSQL
* **ORM:** SQLAlchemy
* **Migrations:** Alembic
* **Authentication:** JWT
* **Containerization:** Docker / Docker Compose

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/dhia619/fastapi-boilerplate
cd fastapi-boilerplate
```

### 2. Configure environment variables

Create your local environment file:

```bash
cp .env.example .env
```

## Running With Docker

Build and start the application:

```bash
docker compose up --build
```

The API should then be available at:

```text
http://localhost:8000
```

Swagger documentation:

```text
http://localhost:8000/docs
```

## Database Migrations

Create a new migration:

```bash
alembic revision --autogenerate -m "migration description"
```

Apply migrations:

```bash
alembic upgrade head
```

Rollback the latest migration:

```bash
alembic downgrade -1
```

If Alembic runs inside your application container, use the equivalent Docker Compose command for your service.

Example:

```bash
docker compose exec api alembic upgrade head
```

## Authentication

The template provides JWT-based authentication using two types of tokens.

### Access Token

Used to authenticate API requests.

```http
Authorization: Bearer <access_token>
```

### Refresh Token

Used to obtain a new access token without requiring the user to log in again.

## Domains

### Auth

Responsible for authentication-related functionality such as:

* login
* token generation
* access tokens
* refresh tokens
* token validation

### Users

Responsible for user-related functionality such as:

* user creation
* user retrieval
* user persistence
* user schemas
* user business logic

The project is structured so additional domains can be introduced without tightly coupling unrelated application logic.

For example:

```text
src/
├── auth/
├── users/
├── products/
├── orders/
└── payments/
```

## Creating a New Domain

A domain can typically contain its own:

```text
domain/
├── models.py
├── schemas.py
├── repository.py
├── service.py
├── router.py
└── dependencies.py
```

## Database

PostgreSQL is used as the default database.

SQLAlchemy handles database interaction while Alembic manages schema migrations.

Typical workflow:

```bash
# Update SQLAlchemy models

alembic revision --autogenerate -m "add new field"

alembic upgrade head
```

Always review autogenerated migrations before applying them in production.
